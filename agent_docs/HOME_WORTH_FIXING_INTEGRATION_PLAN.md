# Home Worth fixing integration plan

## Decision

The redesigned Home Worth fixing experience replaces the deprecated Worth
fixing UI. It is the only product path for Worth fixing: there is no fallback
to the old screen, and fixtures must not be reachable in either development or
production.

The backend will emit a durable Home-shaped finding projection. It is not an
adapter over the deprecated UI. The existing finding and artifact lifecycle
remains the source of truth.

## Data owned by Steward

Steward will persist the interpretation that cannot safely be reconstructed
from counts alone:

- `evidence_note`: a short, evidence-grounded explanation of the observed
  pattern. It must not invent counts.
- `preview_steps`: one to six concise steps describing the proposed handoff.
  They must match the complete handoff body and must not promise automation.

The offer above the fix card is deliberately **not** generated by Steward. It
is deterministic copy selected from the handoff type, such as a prompt,
runbook, or existing capability.

## Deterministic evidence metrics

The Home card will calculate its evidence tiles from retained admissible
evidence, rather than asking a model to produce numbers:

- number of observed instances;
- number of retained evidence records;
- number of distinct observed applications;
- time span from the earliest to latest retained evidence.

The underlying evidence ledger is `findings` plus `finding_evidence` and
`evidence`; see `crates/dystil-insights/src/store.rs :: finding_evidence()` and
`crates/dystil-insights/src/store.rs :: apply_reconciliation_with_attempt()`.

## Lifecycle and actions

- A Home item is a real active Worth fixing finding, not a fixture.
- **Save** uses the existing promotion boundary (`crates/dystil-insights/src/artifact.rs :: keep_finding()`), which creates the existing `artifacts` record and removes the finding from the active queue.
- **Your shortcuts** is the redesigned name and presentation of Ready to use.
  It reads the same accepted artifacts through
  `crates/dystil-insights/src/artifact.rs :: ready_artifacts()`; no shortcut
  table or second lifecycle is introduced.
- Evidence and corrections use the existing retained evidence and disposition
  paths. A user can defer an item without treating it as settled.
- User-entered Ask text must be carried into the existing Ask for a fix flow;
  it must not be discarded on navigation.

## Deferred scope

- Runnable scripts, automation execution, progress jobs, and simulated timer
  jobs are out of scope for this phase. The Home UI must not claim that Dystil
  can run work until that phase exists.
- Redesigning the Ask for a fix surface is out of scope. It retains its current
  interaction model, except that the Home entry point preserves the user's
  initial text.
- User-originated Home-card presentation can be added with the Ask redesign.
  This phase supports Steward-originated Worth fixing findings only.

## Implementation sequence

1. Extend the Steward schema and durable finding projection with `evidence_note`
   and `preview_steps`, including a migration and validation.
2. Add a Home-specific backend response that combines the persisted Steward
   projection with deterministic evidence metrics.
3. Replace the fixture-only Home provider with the real response in every build
   mode; remove fixture data and the mock switch.
4. Wire Save, evidence, correction, and initial Ask-text handoff to existing
   backend behavior. Suppress runnable controls until phase two.
5. Populate Your shortcuts from existing Ready to use artifacts.
6. Regenerate Rust-to-TypeScript bindings and validate migration, backend, and
   frontend integration behavior.
