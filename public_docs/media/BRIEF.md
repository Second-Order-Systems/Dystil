# Media for the README

All README images are **rendered from HTML in `src/`**, not captured from a running
app and not generated by an image model. That is deliberate: the source is diffable,
the text is real text, and when the UI changes the fix is an edit rather than a
re-shoot.

| File | Source | Used in |
|---|---|---|
| `banner-hero.png` | `src/hero.html` | Top of README |
| `banner-loop.png` | `src/loop.html` | "What Dystil does" |
| `screen-worth-fixing.png` | `src/worth-fixing.html` | "Everyone has a solution" |
| `screen-evidence.png` | `src/evidence.html` | Worth fixing |
| `screen-ask-for-fix.png` | `src/ask-for-fix.html` | Ask for a fix |
| `screen-ready-to-use.png` | `src/ready-to-use.html` | Ready to use |

`banner-teams.png` is unused and predates this set.

## Regenerating

```bash
cd public_docs/media/src
CH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"

for f in hero worth-fixing evidence ask-for-fix ready-to-use; do
  "$CH" --headless=new --disable-gpu --hide-scrollbars \
        --force-device-scale-factor=2 --window-size=1600,1000 \
        --screenshot=../$f.png "file://$PWD/$f.html"
done

"$CH" --headless=new --disable-gpu --hide-scrollbars \
      --force-device-scale-factor=2 --window-size=1600,560 \
      --screenshot=../loop.png "file://$PWD/loop.html"
```

Then rename `hero.png` → `banner-hero.png`, `loop.png` → `banner-loop.png`, and the
rest to their `screen-` names. Rendering at scale factor 2 is what keeps the type
crisp when GitHub scales the image down to its content width.

## Keeping them honest

`src/app.css` mirrors the real components — `components/dystil/sidebar.tsx`,
`worth-fixing/finding-card.tsx`, `pages/ask-for-fix.tsx`, `pages/ready-to-use.tsx`
— and the copy in each mockup is the app's own copy where the app has copy.

This is the same standard as the docs split: **a screenshot showing behaviour that
does not exist is the same failure as a document describing an architecture that
does not exist.** If you change one of those components, change the mockup or the
README is lying in a format readers trust more than prose.

The scenario data (the Friday client report, the customer fields, the review
errors) is invented and contains no real names, domains, accounts, keys, or paths.
Keep it that way.

## Conventions

- Files live in `public_docs/media/`, **not** `apps/dystil/public/` — that directory
  is the app bundle and its filenames contain spaces, which is what broke the
  banners on GitHub.
- Kebab-case names, no spaces.
- Light theme. GitHub serves the same file to light and dark readers.
- Keep GIFs under ~5 MB; GitHub serves them uncompressed.
